# Trinity V1.3.2 VTweak 运行时汉化

本工程生成独立的 `TrinityCN.asi`，不修改原始 `Trinity.asi`。英文到中文的映射只在开发阶段保存在
`translations.zh-CN.json`，构建时转换为 C++ 只读数据并编译进 ASI；发布目录禁止携带 JSON。
游戏内右上角版本号前、默认说明栏和 Windows 文件属性均带有 `b站up 改名_汉化` 标注。

物品添加、物品编辑和装备编辑中的动态物品名、分类名、仓库名不属于 Trinity 的静态字符串。
构建脚本会从当前受支持游戏版本的原版 `iteminfo`、`ItemGroupInfo`、`InventoryInfo` 与简体中文 PALOC 中生成
行号锁定的中文回退表，并把目录译文所需字形合并进 ImGui 字体范围；只有 Trinity 自身的本地化
读取失败时才使用该回退，不覆盖原函数的成功结果。
当前 ItemInfo 中 72 个没有官方简中名称的开发、测试或特殊物品会使用人工中文名，并显示为
`[mod] 中文名称`，用于提示它们可能无法由 Trinity 正常加入背包；已有官方名称的物品不会添加该标记。
“添加物品”的一级分类继续使用已验证的精确 RVA 定点翻译与动态 ItemGroupInfo 回退，不直接轮询或
改写 Trinity 的最终分类向量。

## 构建

```powershell
& 'C:\Program Files\PowerShell\7\pwsh.exe' -NoLogo -NoProfile -ExecutionPolicy Bypass -File '.\tools\trinity_localizer\build_trinity_localizer.ps1'
```

构建产物固定为：

```text
dist/trinity_localizer/TrinityCN.asi
```

将其与 `Trinity.asi` 一起交给游戏的 ASI Loader 加载。当前实现严格匹配 Trinity `v1.3.2 VTweak`
（Lian fork）和 ImGui `1.91.5`，动态目录数据严格匹配当前锁定的 Crimson Desert 数据表。
目标版本、字体函数序言、名称 getter 序言或游戏数据表哈希不一致时
会自动拒绝对应功能，不修改 Trinity 的功能逻辑。

VTweak fork 自带 `Trinity_*.ini` 多语言覆盖，但本伴生补丁不依赖该文件，而是直接覆盖完整静态
菜单文本；动态物品名、分类名与仓库名通过 Hook 名称 getter（0x34240）按游戏表行号查中文回退表。
物品使用 ItemInfo 定义 +0x20（表全局 0x1CE200），分类使用 ItemGroupInfo 定义 +0x18（表全局
0x1CE208），仓库使用 InventoryInfo 定义 +0x70（表全局 0x1CE218）。0x34240 的 23 字节序言含
一条 RIP 相对 cmp（检查目录全局 0x1CE220），跳板复制后会重定位该 disp32。

每次游戏启动都会在 `bin64/TrinityCN.log` 覆盖写入运行诊断，包括分类/仓库地址表建立数量和
动态目录中文回退的首次命中结果；该日志不包含游戏存档或用户隐私数据。

旅行传送的顶层分类由 Trinity 在 `kSceneRules` 中硬编码，并非游戏本地化表字段；构建时按当前
v1.3.2 二进制中逐项验证过的 UTF-8 字符串槽翻译。分类内地点仍可能来自场景 key、地区缩写、
固定场景名或游戏节点原名，需按各自生成模式分别处理。

## V1.3.2 实机稳定基线（2026-08-31）

- 已验证成品：`TrinityCN 0.7.3.0`，SHA-256
  `D03E7F096EE695F44D454B2BDB90A1F24F7874763C82826DB73F2014C51D1361`。
- 目标 `Trinity.asi` SHA-256：
  `87E0D9322866F5D399B11E1CC240BA42A97F76E46B729EC86D1D4FB26483F266`。
- 用户实机确认：菜单与“物品 > 添加”页面不再卡顿，当前未发现其他问题。
- 本版本不安装、不依赖作者的 `Trinity_zh.ini`；该文件只用作开发阶段的翻译覆盖审计参考。
- 作者 INI 共 687 个界面键，其中 645 个英文键实际存在于当前 V1.3.2 二进制；0.7.3 的
  `translations.zh-CN.json` 对这 645 项的缺失数为 0。审计必须同时检查功能标题和紧邻说明，
  不能只因标题已汉化就认为该功能覆盖完成。
- 0.7.0 的“等待最终分类向量并直接写入”会导致严重卡顿，尤其是“物品 > 添加”页面；稳定版已
  移除这条链路。后续不得恢复 55 项全命中门槛、分类向量轮询或直接写入，也不得用整表后台预载
  替换此前多版本验证过的按需动态目录 Hook，除非有独立实现、性能证据和完整实机回归。

## 后续 Trinity 更新的强制重分析原则

每次 Trinity 发布新版本，都必须把新 `Trinity.asi` 当作全新的二进制目标，从底层重新走完分析，
不能因为更新日志只写了少量新功能，就只迁移旧 RVA 或补那几条文案。旧版本只能用于比较行为和确认
哪些设计曾经稳定，不能直接继承其地址、容量、调用约定、表结构、分类数量或汉化覆盖结论。

新版本发布汉化前至少重新确认：PE 哈希和版本、section 布局、全部界面字符串及相邻说明、作者 INI
与当前二进制/翻译表的全量差集、字体与版本锚点、动态名称 getter 调用链、表全局与字段偏移、硬编码
分类和旅行规则、游戏表生成数量、Hook 跳板重定位安全，以及菜单和“物品 > 添加”页面的实机性能。
任何实验性轮询、直接改写运行时容器或预载机制，都不得混入常规版本迁移；必须单独验证性能与稳定性。
